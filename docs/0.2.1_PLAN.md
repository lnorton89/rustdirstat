# 0.2.1 sprint plan

Work plan for the fixes in [`docs/0.2.0_REVIEW.md`](0.2.0_REVIEW.md), which
reviewed `main` at `v0.2.0` and rated filesystem correctness 5.5/10 and
destructive-operation safety 5.5/10. The review's bottom line: the project
does not need a rewrite, it needs a **focused filesystem-integrity pass**.
The guiding principle, in the review's own words:

> **A display name, a tree position, and a filesystem object's identity are
> three different things.** Right now `String` names and `Vec<usize>` index
> paths sometimes serve more than one of those roles.

The sprints below follow the review's "Recommended fix order" table (P0
first). Work is ordered so that each sprint leaves the tree compiling,
lint-clean, and test-green — the three CI gates (`cargo fmt --all -- --check`,
`cargo clippy --all-targets --all-features -- -D warnings`,
`cargo test --all-features`) must pass at the end of every sprint, so a
half-finished sprint can be committed and handed off.

Branch: `0.2.1-filesystem-integrity`. Commit after each sprint with a
message naming the sprint.

Platform caveat: a lot of this is `cfg(unix)`-gated (non-UTF-8 names, EXDEV,
inode identity). The unix tests compile to nothing on Windows — verify on
Linux/WSL before pushing. On Windows use
`wsl -e bash -lc "cd /mnt/c/path/to/repo && CARGO_TARGET_DIR=\$HOME/rds-target cargo clippy --all-targets"`.

## Sprint 1 — Filesystem identity: lossless names (review P0 #1 + P1 #5)

**Goal:** no operational path may be derived from lossy presentation text.
`Node.name` becomes `OsString`; the scanner stops retaining `DirEntry`
handles. This is the foundational change the rest of the plan builds on —
the review says the release must not ship with permanent deletion enabled
until this lands.

### Tasks

1. **`src/model.rs`**
   - `Node.name: String -> OsString`.
   - `Tree::path_for` — `path.push(&node.name)` works unchanged (pushing
     `&OsStr` is lossless).
   - `sort_nodes` Name orders — sort keys are presentation, so compare on
     `name.to_string_lossy().to_lowercase()` (preserves current Unicode
     case-folding for valid UTF-8; a lossy sort is a display choice, not an
     identity one).
   - `category_for_name(name: &OsStr)` — extension extraction on the raw
     `OsStr`; a non-UTF-8 extension just yields `None` -> NoExtension/Other.
   - `Tree::placeholder` — root name from `file_name()` as `OsString`.
   - `fixtures::{file, file_sized, dir, deep_chain}` — keep `&str` params,
     store `OsString::from(name)`.
   - Tests: comparisons against `String` literals become
     `name == OsStr::new("x")` or compare via `as_os_str()`.

2. **`src/scanner.rs`** — fold review P1 #5 in here (same lines):
   - Materialize owned entry records before recursing:
     `struct EntryInfo { name: OsString, path: PathBuf, metadata: Metadata }`.
   - `read_entries` returns `Vec<EntryInfo>` (still counting per-entry
     read failures), so the `DirEntry` is dropped before any child scan —
     this is what stops Unix `RLIMIT_NOFILE` exhaustion on deep/wide trees.
   - `scan_dir`, `scan_dir_deep`, `leaf_node`, `unreadable_dir`,
     `finish_dir` take/thread `OsString` names.
   - Root node name from `file_name()` as `OsString`.

3. **Display boundaries** (lossy conversion *only* where text is shown):
   - `src/search.rs` — match regex against `child.name.to_string_lossy()`
     (search is presentation; non-UTF-8 names are simply not text-searchable).
   - `src/top_files.rs` — `TopFile.name` stays `String` (lossy display).
   - `src/report.rs` — name column: `to_string_lossy()`.
   - `src/csv_export.rs` — `path.push(&child.name)` unchanged (lossless
     path); the CSV *cell* stays the lossy display of the path.
   - `src/duplicates.rs` — `path.push(&child.name)` unchanged; paths are
     already `PathBuf` and stay lossless.
   - `src/gui/app/rows.rs` — `TreeRow.name` stays `String` (lossy).
   - `src/gui/app/tools.rs` — `PendingDelete.name: String -> OsString`
     (identity check `node.name != pending.name` must compare raw names);
     display via `to_string_lossy()`.
   - `src/tui/app/operations.rs` — same `PendingDelete.name` change.
   - `src/tui/nested.rs`, `src/gui/treemap_layout.rs` — tile `name` stays
     `String` (lossy display) for labels/legend matching.
   - Both treemap painters + list renderers — labels already take what the
     tile/row gives them; only call sites passing `node.name` to `&str`
     params change to `to_string_lossy()`.

4. **Regression tests** (add where each behavior lives):
   - `cfg(unix)`: a file whose name contains an invalid UTF-8 byte scans,
     `path_for` reconstructs the exact byte sequence, and
     open/delete/copy-path use the exact bytes (scanner or model tests).
   - `cfg(unix)`: two names whose `to_string_lossy()` forms collide (e.g.
     `b"a\xFF"` and `"a\u{FFFD}"`) remain two distinct nodes with two
     distinct paths.
   - Scanner: `read_entries` drops `DirEntry` before recursion (structural —
     the `EntryInfo` type makes it so; assert the tree built from a deep
     chain matches the existing parallel/deep agreement test).

### Done when
- `Node` compiles with `OsString`; no `to_string_lossy` anywhere on a path
  that reaches the filesystem.
- Existing `cargo test`, clippy, fmt pass; the two new unix tests pass.

## Sprint 2 — Destructive-operation safety (review P0 #2, P1 #4, P1 #3)

**Goal:** a move cannot recurse into its own output, Empty cannot silently
leave files behind, and GUI navigation state survives a rescan by identity
rather than by index coincidence.

### Tasks

1. **`src/util.rs` `move_path`** (P0 #2):
   - Canonicalize source and destination *parent* up front; reject when
     `dest` lies within `source` (walk canonical components) — the
     `a -> a/b` recursive-copy explosion.
   - Inspect the rename error: fall back to copy-then-remove only on
     cross-device — `raw_os_error() == Some(libc::EXDEV)` on unix,
     `ERROR_NOT_SAME_DEVICE` (17) on Windows. Every other rename error is
     returned as-is.
   - Regression tests (unix): `a -> a/b`, `a -> a/b/c`, `a -> a`, existing
     destination (already covered), and a rename error that is *not*
     cross-device (e.g. rename onto a path whose parent doesn't exist)
     must not trigger a copy.

2. **Empty-folder partial failure** (P1 #4) — both `confirm_empty`
   (`src/gui/app/tools.rs`) and the TUI `confirm_empty`
   (`src/tui/app/operations.rs`):
   - No `filter_map(Result::ok)` in mutation code: enumerate all direct
     children first, fail the operation (report) if enumeration is
     incomplete; then delete each child, collecting per-child results, and
     report how many failed if any did — a partially emptied folder is not
     "Emptied: …".
   - Best-effort: on partial failure, still rescan the affected subtree so
     the in-memory tree matches the on-disk truth (the review's
     "perform operation, rescan affected directory" model).

3. **GUI rescan restoration by path identity** (P1 #3) —
   `src/gui/app/scan.rs` + the rescan path in `src/gui/app/mod.rs`:
   - Before replacing the tree, capture the zoom/selected/expanded
     locations as lossless relative path components (walk `path_for`'s
     result relative to `root_path` — components are already `OsString`).
   - After the new tree arrives, resolve those components against the new
     tree to fresh index paths (walk `root_path` + components through
     `children` by name; sibling order is not stable between scans).
   - Regression test (GUI ui tests): scan a fixture, swap in a second scan
     with a reordered sibling set, assert selection/zoom land on the same
     *name* not the same *index*.
   - The TUI already restores by path components — mirror its approach.

### Done when
- `move_path` rejects self-descendants and only copies on EXDEV; the five
  review scenarios are regression-tested.
- Empty reports incomplete enumeration/partial failure instead of a blanket
  success.
- GUI rescan restores by name; the sibling-reordering test passes.

## Sprint 3 — Accounting and responsiveness (review P1 #6, P1 #7, P1 #8)

**Goal:** hard links no longer make duplicates/disk accounting lie; whole-
volume scans stay on their filesystem; the GUI stops freezing on search and
extension aggregation.

### Tasks

1. **File identity for duplicates** (P1 #6): on unix capture
   `(st_dev, st_ino)` per file at scan time (store on `Node`), and let
   duplicate detection distinguish hard-link aliases from duplicate content
   (same inode = one "real" copy; never claim reclaimable space for
   aliases). Physical-size accounting policy for hard links: document and
   implement a choice (e.g. count allocated blocks once per inode per tree).
   Windows: volume serial + file ID behind the same abstraction.
2. **Same-filesystem boundary** (P1 #7): record the root's `st_dev`; the
   scanner stays on that device by default, with an explicit escape hatch.
   Unix-only for now.
3. **GUI search off the frame thread** (P1 #8): background `search::search`
   through the existing channel pattern; cancellation/debounce if cheap.
4. **Extension aggregation iterative + off-thread** (P1 #8):
   `collect_extensions` becomes iterative; large-subtree aggregation runs
   on the worker thread.

### Done when
- Two hard-linked files are not reported as reclaimable duplicates; their
  combined physical size is not double-counted (unix test using `link(2)`).
- Scanning `/` does not descend into other devices (unix mount-boundary
  test, best-effort in CI).
- Typing in the GUI search box does not block the frame thread; zooming a
  large subtree does not stall.

## Sprint 4 — Windows and CI (review P1 #9, P1 #10, P1 #11, P2 #17)

### Tasks

1. **`vssadmin delete shadows`** (`src/wintools.rs`): build the argument as
   one token `/for=<volume>`; fix the tool's description to match
   Microsoft's "client-accessible shadow copies" wording.
2. **GitHub Actions hardening** (`.github/workflows/*.yml`): pin every
   third-party action to a full commit SHA (`actions/checkout`,
   `Swatinem/rust-cache`, `dtolnay/rust-toolchain` — the `@master` one is
   the priority); split the release workflow so build jobs run
   `contents: read` and only the publish job holds `contents: write`.
3. **Branch protection** (P1 #10): this is a GitHub repository setting, not
   a repo file — enable "require status checks" on `main` (CI test job,
   branch up to date, block force-push and deletion) in the settings UI,
   and record it here when done.
4. **CLI mode conflicts** (P2 #17): `--no-tui` conflicts with `--csv`
   (`clap` `conflicts_with` or `ArgGroup`); add an integration test beside
   `tests/cli.rs`.

### Done when
- `vssadmin` invocation matches documented syntax; wording is exact.
- Workflow YAML has no unpinned third-party action and least-privilege
  `permissions`; `main` protection is enabled (settings, manual).
- `rustdirstat --no-tui --csv out.csv .` is rejected by clap.

## Handoff notes

- **Do not hand-edit line endings.** Repo is LF-normalized via
  `.gitattributes`; `CLAUDE.md` may appear CRLF in the worktree — git
  normalizes on commit.
- **Commit only what you changed, by name** (`git commit -- path` if other
  work is staged). The tree may carry another agent's in-flight edits.
- **`Node` drop, treemap, and cache-key invariants** are load-bearing; see
  `docs/ARCHITECTURE.md` and `docs/PERFORMANCE.md` before touching draw
  paths. Nothing in these sprints should touch a per-frame path.
- **The `name` field change is the wide one**: ~98 call sites across both
  front ends. Grep for `.name` and `category_for_name(` when resuming.
- `cargo test` on Windows runs unit tests only (`tests/quit_stress.rs` and
  the unix-gated tests compile to nothing); verify unix behavior in WSL.
