## What is genuinely fixed

### P0 filename identity issue

The `Node.name` migration to `OsString` is the right fix. Operational paths now preserve exact filesystem names, while lossy conversion is kept at display/search/sort boundaries.

The scanner also materializes an owned `EntryInfo` instead of carrying `DirEntry` values into recursion. Unix regression tests cover both non-UTF-8 filenames and distinct filenames whose lossy displays collide.

Relevant files:

- `src/model.rs`
- `src/scanner.rs`

### P0 move safety issue

`move_path()` is substantially better. It now:

- rejects destinations inside the source directory;
- only falls back to copy/delete for actual cross-device failures;
- returns ordinary rename failures as-is;
- preserves symlinks during fallback;
- removes partial destination copies after failed copies;
- uses iterative directory traversal.

Relevant file:

- `src/util.rs`

# Merge blocker 1 — release workflow artifact collision

Every build-matrix job uploads an artifact with the same name:

```yaml
- name: Upload build artifacts
  uses: actions/upload-artifact@...
  with:
    name: release-assets
    path: dist/
```

With `actions/upload-artifact@v4`, separate matrix jobs cannot all create the same named artifact. The first can succeed and later jobs can fail with an artifact conflict.

Use one artifact name per target:

```yaml
- name: Upload build artifacts
  uses: actions/upload-artifact@...
  with:
    name: release-assets-${{ matrix.target }}
    path: |
      dist/*.zip
      dist/*.tar.gz
      dist/*.sha256
```

Then merge them in `publish`:

```yaml
- name: Download archives
  uses: actions/download-artifact@...
  with:
    pattern: release-assets-*
    path: dist
    merge-multiple: true
```

Relevant file:

- `.github/workflows/release.yml`

# Merge blocker 2 — release job uploads too much

The workflow currently uploads all of `dist/`, including both final archives/checksums and staging directories. The publish job then uploads every file it finds.

The Actions artifact should contain only:

```yaml
path: |
  dist/*.zip
  dist/*.tar.gz
  dist/*.sha256
```

That prevents raw binaries, README, LICENSE, and staging files from becoming unintended release assets.

# GUI rescan identity is improved, but selected items still have an unsafe edge case

Rescan restoration now captures raw `OsString` name components and re-resolves them against the new tree. That fixes the old sibling-index instability.

However, `resolve_identity()` returns the deepest surviving ancestor when the complete path no longer exists.

That is acceptable for **zoom**, but not ideal for **selection**.

Example:

```text
folder/
└── important.txt   <- selected
```

If `important.txt` disappears before the rescan completes, the resolver can return `folder`, silently changing the selected object from the vanished file to its parent directory.

Use two modes:

```rust
resolve_identity_prefix(...)
resolve_identity_exact(...)
```

Recommended behavior:

```text
zoom:
    deepest surviving ancestor is okay

selected:
    exact match or None
```

Add a regression test:

```text
select folder/file.txt
rescan where file.txt vanished but folder remains
selected_path == None
```

Relevant file:

- `src/gui/app/scan.rs`

# Hard-link duplicate reclaimability is fixed, but disk accounting is not

The duplicate subsystem is now hard-link-aware on Unix and computes reclaimable space from distinct filesystem objects rather than pathname count.

That fixes the dangerous duplicate-space claim.

But the main filesystem tree still sums each hard link's `physical_size` independently. There is no scanner-wide inode deduplication for allocated-block accounting.

So the correct status is:

```text
Duplicate reclaimable accounting: FIXED
Physical-size tree accounting:     OPEN
```

Relevant files:

- `src/duplicates.rs`
- `src/platform.rs`
- `src/scanner.rs`

Windows hard-link identity remains deferred.

# Extension aggregation is only partially fixed

`collect_extensions()` is iterative now and initial scan-time extension aggregation runs off the UI thread.

However, `refresh_extensions()` still walks the whole zoom subtree synchronously:

```rust
pub fn refresh_extensions(&mut self) {
    self.extensions =
        collect_extension_rows(self.zoom_node(), self.use_physical);
    self.sort_extensions();
}
```

So large zoomed subtrees can still cause GUI stalls.

Status:

```text
recursive aggregation:          fixed
post-scan UI-thread traversal:  fixed
zoom-time UI-thread traversal:  still present
```

Relevant file:

# Updated merge recommendation

Before merging:

1. **Fix the release matrix artifact-name collision.**
2. **Upload only archives/checksums through the Actions artifact pipeline.**
3. **Make vanished GUI selections restore to `None`, not an ancestor.**
4. Either fix hard-link physical-size accounting or explicitly mark it deferred rather than complete.

Then merge with these known follow-ups:

- Windows allocated/physical size;
- Windows hard-link identity;
- exact-by-default `node_for` / `path_for`;
- asynchronous extension refresh;
- `cargo-deny` CI enforcement;
- cross-device move metadata preservation;
- README screenshots/product restructuring;
- GitHub `main` branch protection.

# Bottom line

The key improvement is that the branch no longer has the broad "do not trust this application to manipulate arbitrary real files" problem from the original review.

The lossless-name migration and move hardening eliminate the two most serious filesystem-integrity defects.

The remaining problems are much more contained.

The release workflow artifact collision is the immediate hard blocker. The GUI vanished-selection behavior is the remaining code-side safety edge case I would fix while this branch is still explicitly focused on filesystem integrity.
